# Link Map Output Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Write `<output>.map` next to every linked `.prg`, using the SDK linker's own map output, so users can see symbol addresses, sizes, sections and free space.

**Architecture:** `Linker.link` already invokes `mos-c64-clang` with the `.ll` modules and `-o <prg>`. Add `-Wl,-Map=<output>.map` to that one invocation; lld writes the standard map file with VMA/LMA/size rows for sections, object files and symbols. No map parsing or demangling: the raw lld map is the source of truth. The map is always written, next to the program, so `-d` is not required to get it.

**Tech Stack:** Kotlin 2.2.10 (JVM 21), Gradle 8.13, JUnit 5.11.4, LLVM-MOS SDK v23.2.0 (`mos-c64-clang` with lld), VICE only indirectly (no new runtime test).

**Spec:** `TODO.md` line 86 — "**Link map** in the output — the CLI note '(no link map in v1)'." CLI surface: `src/main/kotlin/pl/qus/wolin/driver/Main.kt:12-22`; link command: `src/main/kotlin/pl/qus/wolin/driver/Linker.kt:40-42`.

## Global Constraints

- Map path is exactly output + `.map`: `-o hello.prg` writes `hello.prg.map` in the same directory.
- The map flag is one `ProcessBuilder` argument, `-Wl,-Map=<path>`, so paths with spaces work without shell quoting.
- The `.prg` bytes must not change; the map is a linker side output.
- Do not parse, reformat, demangle or post-process the map.
- `validate` (compile-only) does not write a map.
- `*.map` is already git-ignored; update `make clean` to remove example maps.
- Conventional commits: `feat(cli): …`.

## Review Focus

1. **Custom output directory.** `-o /tmp/x/y.prg` writes `/tmp/x/y.prg.map`, never the cwd or the input directory. → pinned by `compiling writes a link map next to the prg`.
2. **Usable content.** The map must contain a symbol line for `main` with address and size, not just section totals. → pinned by the same test's `main` regex.
3. **Paths with spaces.** A temp directory containing a space must still produce the map; a split `-Wl,-Map` argument would break. → pinned by `the link map path supports directories with spaces`.
4. **Link result unchanged.** Adding the flag must not alter the `.prg`; the existing `compiling produces a prg` test stays green and the full suite passes.
5. **Stale docs.** Main usage and README must no longer say "(no link map in v1)"; map behavior and cleanup are documented. → pinned by the doc edits and grep.

```kotlin
    fun link(llFiles: List<Path>, output: Path, workDir: Path) {
        val map = output.resolveSibling(output.fileName.toString() + ".map")
        run(
            listOf("-O2") + llFiles.map { it.toString() } +
                listOf("-o", output.toString(), "-Wl,-Map=$map"),
            workDir,
        )
    }
```
